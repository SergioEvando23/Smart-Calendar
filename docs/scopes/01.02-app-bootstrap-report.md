## Relatório de Implementação — Escopo 01.02

### 1. Resumo executivo

Foi inicializado o bootstrap Web e API: uma página React técnica consulta a prontidão da API Fastify; a API fornece liveness e readiness, usa Prisma para sondar PostgreSQL e possui configuração de ambiente, CORS restrito, logs e encerramento seguro. Docker Compose agora declara Web, API e PostgreSQL, preservando Ollama como perfil opcional.

### 2. Status

PARCIALMENTE CONCLUÍDO

As validações locais de lint, tipo, testes, build, Prisma Client e estrutura passaram. Não foi possível executar Docker Compose, conectar a API a um PostgreSQL real, aplicar migrations no container ou validar a integração Web → API em runtime porque Docker CLI não está disponível neste ambiente.

### 5. Arquitetura implementada

- Inicialização Web: Vite monta React/TypeScript e apresenta estado de conectividade.
- Inicialização API: Fastify cria servidor com logging, CORS de origem única, tratamento centralizado de erros e desligamento seguro.
- Integração HTTP: cliente tipado consulta `GET /health/ready`, com timeout e normalização de falhas.
- Integração Prisma: datasource PostgreSQL, cliente singleton e sonda `SELECT 1` na prontidão. Não há migration inicial porque não existem modelos.
- Comunicação Docker: Nginx serve a Web e encaminha `/api/` para `api:3000`; banco e API permanecem internos.
- Tratamento de erros: mensagens públicas são genéricas; detalhes de banco ficam apenas nos logs estruturados da API.

### 8. Segurança

- CORS aceita somente `WEB_ORIGIN` configurada; métodos permitidos limitam-se a `GET`.
- `.env` permanece ignorado e `.env.example` usa somente placeholders locais.
- Somente o serviço Web publica porta; PostgreSQL e API usam rede interna do Compose.
- Falhas de healthcheck não expõem detalhes do banco à resposta HTTP.
- Risco remanescente: `npm install` reportou 8 vulnerabilidades transitivas (1 moderada, 5 altas e 2 críticas). Elas requerem triagem e atualização compatível; não foi executado `npm audit fix --force` para evitar atualização destrutiva.

### 9. Pendências

- Instalar/disponibilizar Docker Compose v2 e executar as validações de runtime pendentes.
- Acrescentar `WEB_PORT` e `WEB_ORIGIN` ao `.env` local já existente, ou recriá-lo a partir de `.env.example`.
- Definir a plataforma Mobile antes de implementá-la.
- Criar a branch `develop` e definir a política de proteção de branches manualmente; ela não existia no remoto/local na execução deste escopo.
